# 阶段 5 每日推荐规则
## 生成前先读
1. `Q-questions.md`：当月问题、本周子问题
2. `weeks/` 本周计划：本周输入要求、上周日回顾写下的「推荐调整」
3. `profile.md`：主阵地、语言能力、阅读预算、跨界领域、拉黑主题
4. `sources.md`：已关注清单（不推）、口味判断、来源偏好
5. `pushed.jsonl` 最近 14 天：已推过的人和链接（不重复）
6. `feedback.jsonl` 最近 30 天：各栏目和来源类型的有用、没用、太浅
当月没有问题时，不推送，改走月度追问。
## 搜索策略
用当前环境里能拿到实时结果的工具：网页搜索、网页抓取、X 搜索、播客和视频字幕工具等。按工具能力挑，一个工具失败就换另一个，不要因为一个工具失败就放弃某一栏。
先用当月问题和本周子问题生成 3 到 5 组搜索词，中英文各一套。英文词优先用从业者会用的说法（例：`"how I got" first 100 paying users`、`teardown`、`postmortem`、`what worked`），中文词加上「复盘」「实测」「后台数据」等。
| 栏目 | 去哪找 | 合格标准 |
|---|---|---|
| 一线实践 | X 上从业者的帖子和长推、个人博客、Indie Hackers、Reddit 的从业者子版块、即刻 | 作者本人做过这件事；有数字、截图或可复现的步骤；最近 30 天内优先 |
| 深度材料 | 作者本人的长文、官方文档和工程博客、长访谈和播客文字稿、论文 | 原始出处；标阅读时长（页面标注或按 300 到 400 字每分钟估算，注明是哪种）；长度符合用户的阅读预算 |
| 一个人 | 从当天其他条目的作者里延伸；搜「问题关键词 + 作者名」；看高质量帖子下的高质量回复者 | 不在已关注清单里；两周内没推过；能指出他最值得先读的一条具体内容；每周至少 1 位来自圈外 |
| 一个反面观点 | 搜「问题关键词 + overrated / doesn't work / against / 反思 / 踩坑」；看高赞帖下的反驳 | 有论证或证据，不是情绪；和主流看法或和用户画像里的倾向相反 |
| 一个输出题 | 不用搜，从今天前 4 条里提炼 | 只有用户自己的经历能回答；能在主阵地上一条帖子说完 |
周日额外：
| 栏目 | 去哪找 | 合格标准 |
|---|---|---|
| 一本书 | 豆瓣、出版社页面、作者官网、Goodreads 核对书名作者和目录 | 真实存在，写明作者；指定只读哪一章，章节名以目录为准 |
| 一个跨界输入 | 从画像里的跨界白名单轮换领域（本周用过的下周换一个） | 那个领域里的一线手艺人讲自己的方法；能迁移到当月问题上 |
| 一次回顾 | 读本周 `R/` 和 `feedback.jsonl` | 列出本周推过的条目编号，问哪条用上了、哪条看了标题就划走 |
## 筛选顺序
对每个候选按顺序过，一条不过就丢：
1. 和当月问题有关吗？说不出关系就丢
2. 是新闻汇总、融资消息、模型发布的跟风讨论吗？是就丢，除非它改变了用户能做出什么
3. 是用户大概率已经刷到的热门吗？（发在头部账号、24 小时内大量转发、已关注的人发的）是就丢
4. 两周内推过这个人或这个链接吗？推过就丢
5. 是二手转述吗？能找到原始出处就换成原始出处
6. 难度合适吗？对照 `sources.md` 的难度基线和「太浅」反馈
最后检查整周比例：本周已推内容里圈外占比低于 20% 时，今天优先选圈外的人或圈外的反面观点。
## 核实
每条推送前都要做：
- 打开链接，确认能访问，标题、作者、日期和你写的一致
- 引用的数字、截图描述，以原文为准；原文没有的不写
- X 帖子尽量用接口或抓取确认帖子和账号真实存在
- 打不开、要登录、或抓取被拦的，换一条；实在没有替代就写明「链接需要登录，我没能核实全文」
- 书核对书名、作者、出版社和章节目录
所有核实结果写进末尾的「核实情况」一行。
## 输出格式
```
今日推送，MM 月 DD 日，月度问题：……
本周子问题：……
1. 一线实践
是什么：……
为什么和本月问题有关：……
看完做什么：……
链接：……
2. 深度材料
是什么：……（阅读约 N 分钟，页面标注 / 我的估算）
为什么和本月问题有关：……
看完做什么：……
链接：……
3. 一个人
是什么：……（他是谁，一句话）
为什么和本月问题有关：……
看完做什么：先读他的这一条，然后……
链接：……
4. 一个反面观点
是什么：……
为什么和本月问题有关：……
看完做什么：……
链接：……
5. 一个输出题
是什么：（问题本身）
为什么和本月问题有关：……
看完做什么：今天在 [主阵地] 发一条，……
核实情况：……
回复「有用」「没用」「太浅」或「换题：xxx」，可以加编号，例：「3 有用」。
```
写作要求：
- 每条最多 4 行，每行一句
- 「看完做什么」必须是今天能做完的具体动作，带动词和产出物（例：写下 3 个、改出两个版本、发一条）
- 中文，口语化，不寒暄，不总结，不用破折号，不用「不是 X，是 Y」句式
- 某一栏没找到合格的，写「今天没找到合格的，原因：……」，不凑数
## 写入
1. 推送原文写入 `R/YYYY-MM-DD.md`（周日加餐写入 `R/YYYY-MM-DD-周日.md`）
2. 每条往 `pushed.jsonl` 追加一行，字段见 `templates/jsonl-schema.md`
3. 推荐的人如果用户回了「有用」，问一句要不要加进 `sources.md` 的已关注清单
## 样例
以下是一份跑通的推送，月度问题为「什么内容会爆？我在读者心里是谁？」。只用来看格式和颗粒度，链接以实时搜索为准，不要复用。
```

链接：（实时核实过的 X 帖子链接）
2. 深度材料
……
5. 一个输出题
是什么：你数据最好的一条内容，和真正帮你招来付费客户的一条，是同一条吗？
为什么和本月问题有关：如果爆款和定位指向两群人，账号会越做越分裂，这题只有你能答。
```
