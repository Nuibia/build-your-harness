# 阶段 6 建定时任务
## 建之前确认四件事
1. **调度器在哪跑**
   - 本机任务（例：Claude 桌面版的定时任务、Codex 自动化、本机 cron）：能读本地档案和本 Skill，优先用这个
   - 会话内循环（例：Claude Code 的 CronCreate、/loop）：会话关掉就停，只适合试跑
   - 云端任务（例：云端 routine、豆包工作、ChatGPT 定时任务）：通常读不到本地文件和本地 Skill，要把档案要点直接写进提示词，并告诉用户档案更新后要同步改提示词
2. **时区**：先查本机时区（`date +%Z` 或 `readlink /etc/localtime`），和用户时区不一致时，换算后再填小时数，并在提示词里写明用户时区。例：本机是 America/Los_Angeles，北京每天 08:00 要填本机前一天 16:00（美国夏令时期间填 17:00）。填完后核对下一次运行时间
3. **推送到哪**：默认写本地文件。要发到飞书、邮件、IM 时，属于对外发送，需要用户明确同意，并先检查登录状态
4. **权限**：定时任务全程不能询问用户，提示词里写清楚失败时怎么办（记日志，不重试到死）
建完后列出每个任务的名称、下一次运行时间（换算回用户时区）、产出位置，请用户核对。
## 提示词模板
把 `{}` 里的内容换成实际值。档案目录用绝对路径。
### 1. 每日推荐
```text
你在 {工作区绝对路径} 执行 space-APQR 每日推荐。全程自动完成，不要询问。
【开始前】
1. 如果工作区有 AGENTS.md 或 CLAUDE.md，先读并遵守。
2. 读 space-APQR Skill 的 SKILL.md 和 references/daily-push.md，按其中规则执行。
3. 读档案目录 {档案绝对路径} 下的 Q-questions.md、本周 weeks/ 文件、profile.md、sources.md、pushed.jsonl 最近 14 天、feedback.jsonl 最近 30 天。
【执行】
1. 今天是 {用户时区} 的日期。当月没有月度问题时，不推送，只在 R/ 下写一行「当月问题未设定，等待月度追问」，然后结束。
2. 按当月问题和本周子问题，用实时搜索找材料，生成最多 5 条推送：一线实践、深度材料、一个人、一个反面观点、一个输出题。
3. 每个链接都要实时核实能打开，作者和数字以原文为准。不确定就写不确定，找不到合格的就写没找到，不凑数。
4. 中文，口语化，每条不超过 4 行，不寒暄，不总结，不用破折号。
【产出】
- 推送原文写入 {档案绝对路径}/R/YYYY-MM-DD.md。
- 每条往 {档案绝对路径}/pushed.jsonl 追加一行（只追加）。
- {推送渠道说明，例：同时作为本次任务的最终回复输出 / 推送到飞书文档 xxx}
【硬约束】不 commit，不 push；不把密钥写进文件或输出；不删除任何文件。
【结束后】{工作区有日志文件时：往 xxx 追加一行，task 为 apqr_daily，写明条目数和文件路径}
```
### 2. 周日加餐与下周计划
```text
你在 {工作区绝对路径} 执行 space-APQR 周日加餐。全程自动完成，不要询问。
【开始前】同每日推荐，另外读 references/goal-ladder.md 的「周计划」部分，以及本周 R/ 下的全部推送。
【执行】
1. 生成周日加餐：一本书（真实存在，写明作者，指定只读哪一章，章节以目录为准）、一个跨界输入（从 profile.md 的跨界白名单轮换，和上周不同领域）、一次回顾（列出本周推过的条目编号，问用户哪条用上了、哪条划走了）。
2. 统计本周 feedback.jsonl：各栏目有用、没用、太浅的次数，写成 2 到 3 条「下周推荐调整」。
3. 按 Q-questions.md 里下周的子问题，写下周完整计划到 weeks/YYYY-Www.md，包含输入、输出、行动、回顾问题、推荐调整。下周跨月时，用下个月的问题；下个月没有问题时，计划里写明「等待月度追问」。
【产出】
- 加餐原文写入 R/YYYY-MM-DD-周日.md，条目追加到 pushed.jsonl。
- 下周计划写入 weeks/。
【硬约束】同每日推荐。
【结束后】{日志说明，task 为 apqr_weekly}
```
### 3. 月度追问
```text
你在 {工作区绝对路径} 执行 space-APQR 月度追问。全程自动完成，不要询问。
【开始前】同每日推荐，另外读 A-area.md、P-projects.md。
【执行】
1. 读 Q-questions.md 里本月问题的「月底应该能回答出什么」，生成 3 个验收问题，请用户用 3 句话回答本月问题。
2. 看下个月是否已有问题：
   - 已有：写明下个月的问题，问用户要不要改。
   - 没有：请用户用一句话给出下个月的方向。不要自行猜题，不要往 Q-questions.md 写任何新问题。
3. 如果锁定的问题只剩 1 个月，提醒用户回到年度目标做一次复盘。
【产出】把以上内容写入 R/YYYY-MM-月度追问.md，并作为本次任务的最终回复输出。
【硬约束】同每日推荐。
【结束后】{日志说明，task 为 apqr_monthly}
```
## 用户回复追问之后
用户在对话里给出下个月方向时（定时任务本身问不了用户，这一步发生在用户下次打开对话时）：
1. 按 `references/goal-ladder.md` 的 Q 部分补全成问题句，过四条检验，请用户确认
2. 写入 `Q-questions.md`，拆好周子问题
3. 如果用的是云端任务、问题写死在提示词里，同步更新三个任务的提示词
